# SKILL-422 subtask 2: Goal finalization and public state

## Scope

Audit and repair parent aggregates, durable planning, child outcomes, finalization, telemetry reconciliation and administrative closure, then reconcile common projections and consumers. The pass is one coherent commit because terminal provenance and exact parent/run identity must reach readers together. Remove mutation authority from read-only status rather than patching one CLI flag.

Preserve SKILL-414 individual-record compatibility and checked verify writes; SKILL-417 parked parent versus operator pause and live finalization ordering; SKILL-418 common board/detail projection, CLI-only desktop access and missing/stale diagnostics. Generic terminality cannot prove successful execution. Existing durable provenance is the first choice for counts and notifications; add a public discriminator only if demonstrated consumer needs cannot be met by current payload facts.

## Acceptance Criteria

1. The inventory and matrix contain source-cited planning, child outcome, goal control/session/progress, finalization, telemetry maintenance, verify and projection transitions. They identify authoritative lifecycle versus aggregate/telemetry evidence and exact repository/issue/parent/subtask/run identity. evidence_subtask_2.md and findings-register.md include ranked findings and explicitly verified areas, retaining the full trigger/evidence/owner/reproduction fields from subtask 1.
2. Parent completion requires admitted finalization evidence or an explicit accepted no-change outcome. Completed children alone leave PR/monitor work visible. Finalization preserves completed/skipped/no-change child work across restart, monitor failure/repair, resume, archived specs and remote branch deletion. Duplicate or conflicting finalization/finish/segment events cannot reopen a terminal parent or complete a different run. Merged PR monitoring ends independently of checks; missing/empty goal checks remain pending; failed/timed-out finalization has a durable block reason.
3. Durable standalone planning stores/imports the required checkpoint/spec bundle before reporting completion and refuses completed key-only settlements without that bundle. Changed intake cannot silently replace a resumable plan. Replan retains admitted completed/skipped subtasks. Interrupted capture/import, no-change decisions and child outcome recovery preserve the durable evidence needed for an intentional continuation.
4. Abandonment, cancellation, operator stop, supersede and purge have separate documented effects on lifecycle, child propagation, ownership release, reasons, pending work, checkpoints and audit history. Administrative closure never manufactures phase execution or commit evidence. Purge refuses live/unknown ownership, scopes owned records, retains the documented spec/recovery evidence and does not delete unclassified rows. Telemetry staleness cannot regress supported completed state or invent lost segment history.
5. Read-only goal status/watch, work list/status/board/detail, CLI/MCP and IDE projection paths cannot prune Git recovery refs, renew leases, fabricate activity/timestamps or mutate lifecycle meaning. Checkpoint pruning stays at the existing authorized runtime post-push/manifest-commit mutation owner. Reconciliation, when required, has an explicit mutation owner and observable durable result. Exact live process evidence without an admissible valid lease does not silently establish running.
6. Aggregate reads retain healthy records beside malformed, incompatible, unrelated and obsolete records with bounded typed diagnostics and preserved rejected evidence. Explicit access to a corrupt identity still reports typed rejection. Selection is deterministic across historical executions and repository/branch/store changes. Limit handling cannot let a rejected first row hide otherwise eligible healthy rows. Legacy completion without newer markers remains terminal and cannot be revived by unrelated child heartbeat or stale lease.
7. Shared projection and desktop/tray/IntelliJ consumers agree on lifecycle, current finalization step, ownership, block reason, completion provenance and freshness. Abandoned/cancelled/superseded terminal rows cannot increment successful Done counts or emit goal_completed notifications. Absent database, stale last snapshot, unknown execution and healthy empty work remain distinct. Board retention stays 6h/24h/7d with default 24h; a 6h window does not claim complete Done 24h coverage. SKILL-417 older-sequence live parent finalization and same-run terminal monotonicity remain supported.
8. Tests assert parent/planning restart, conflicting finishes with unavailable telemetry emission, pause/abandon/purge/resume outcomes, read-only ref/row preservation, malformed-row isolation, exact identity liveness/selection, legacy terminal projection and consumer notification/count/ordering consistency. Tests use durable/public boundaries and named realistic regressions; existing meaningful evidence remains. Changed board diagnostic tokens or successful-terminal facts include schema/enum/key/version/failure and producer/consumer parity coverage only where demonstrated necessary.
9. Documentation and diagnostics describe the resulting contracts and any supported limitations. evidence_subtask_2.md records source-based architecture checklist results, reproduction definitions and pending execution closure; it never substitutes reset, archived prose or telemetry for completion evidence. No swallowed verify artifact failure, stop/recovery failure or skipped record stays silent. No guard, baseline or exemption widens.
