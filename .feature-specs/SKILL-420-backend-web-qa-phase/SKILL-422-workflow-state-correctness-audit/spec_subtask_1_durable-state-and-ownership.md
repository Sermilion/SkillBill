# SKILL-422 subtask 1: Durable state and ownership

## Scope

Establish the full inventory and matrix, then audit and repair the durable workflow/phase and process/control ownership boundaries. This pass owns source-confirmed terminal monotonicity, atomic write acknowledgement, attempt/settlement acceptance, takeover fencing, verified running, finite owner renewal and truthful stop results. Preserve required phase-write-before-in-memory ordering, compatible legacy completion and deliberate recovery identity. Investigation ends in bounded findings with an owning path, not a generic refactor.

Start at DatabaseSchema, DatabaseSchemaStatements and FeatureTaskPhaseSettlementsMigration. The registry alone is incomplete. Classify all tables listed in implementation_plan_subtask_1.md, discover omitted stores from the actual schema/migrations during later implement, and inventory steps_json/artifacts_json, manifests, planning projections and Git checkpoint refs. Later source citations must name actual path and symbol; the digest's leads are not fresh verification.

## Acceptance Criteria

1. state-ownership-inventory.md covers every discovered table/store/artifact family and labels each as authoritative, derived/checkpoint, cache, telemetry-only or supporting evidence/configuration. It traces every lifecycle writer and trigger through engine, persistence, CLI/MCP and projection consumers, with transaction ownership and identity. It explicitly includes feature_task_phase_settlements and distinguishes it from schema registry entries.
2. transition-matrix.md separates lifecycle, phase/step, liveness, freshness, controls, progress and display categories. Each supported transition names actor, identity, prior/target vocabulary, required evidence, transaction write set, recovery/replay behavior, terminal meaning, resumability and consumer effect. Creation/admission, pause request/boundary, stop/abandonment, recovery/rerun and child/parent finalization remain distinct. Unsupported cancelled/interrupted/superseded/idle workflow states are documented without invented enum values.
3. findings-register.md and evidence_subtask_1.md classify and rank the audited durable/ownership scenarios. Every entry contains severity, concrete trigger, exact affected identities, before/after evidence or its pending capture recipe, root cause, production owner and isolated reproduction. Source candidates are not labelled reproduction-confirmed; explicitly verified no-finding areas carry source and test evidence. Repair entries preserve rejected bytes and historical outcomes.
4. Workflow, phase and settlement write paths reject demonstrated terminal regressions, superseded attempts, contradictory settlement and stale-owner writes at their durable boundary. Required coupled phase output, ledger, attempt, checkpoint and workflow state changes share the owning transaction where the scenario requires atomicity. Save/commit refusal cannot return an accepted completion. Explicit recovery and rerun retain identity, history and admissible continuation semantics.
5. Worker and parent-control ownership paths require the admitted identity, token/generation and verified process evidence for destructive action and running status. Demonstrated old-owner writes after takeover cannot overwrite newer or terminal records. Expiry, renewal, live-but-expired, foreign host, PID reuse, unsupported inspection, reservation crash and clock behavior have distinct outcomes and diagnostics. Crash reconciliation has one mutation owner and rechecks current durable evidence atomically.
6. Standalone phases retain a finite lease. If the long-running owner scenario proves renewal necessary, a deliberate owner-only renewal path preserves CAS fencing and finite expiry; no reader renews it. Terminal late events cannot resurrect a superseded monitor. Goal stop retains the operator pause request while reporting unverified, failed or incomplete termination honestly, with a typed result and diagnostic instead of false STOPPED success.
7. Named production-boundary regression tests assert reopen durability, pre/post-commit failure behavior, terminal/attempt/settlement contradictions, old-owner fencing, expiry/renewal/takeover, control JSON race preservation and failed stop truthfulness. Tests use explicit isolated environments and owned processes, assert outcomes rather than interactions, and preserve existing takeover and planning database-failure regressions. Each added test names its realistic bug and criterion/finding.
8. Contracts and diagnostics for changed durable/ownership seams have one owner, declared wire keys and supported compatibility handling. Any demonstrated schema change includes owner pins, typed parse failures and parity tests. evidence_subtask_1.md records A1-A12 and G1-G7 applicability and source-based results without claiming tests executed. No guard, baseline or exemption widens.

### Implementation sequence

1. Confirm current owners and policies only after separate implementation authorization. Establish the inventory and family transition matrix before choosing repairs. Trace CLI/MCP mutation requests to their actual transactional owner. Record which enum states are legal per family and whether timed_out is terminal there; do not generalize from the generic terminal set.
2. Define isolated before/after scenarios for terminal workflow replacement, phase completion, settlement contradiction and stale attempt. Trace all explicit retry/reentry APIs so a monotonicity rule rejects late writes while still admitting intentional recovery/rerun with historical identity. Preserve legacy authoritative completion without requiring newly added markers.
3. Audit the complete ownership path through admission, acquisition, reserve, verified termination, re-admission, transfer, heartbeat, accepted phase write, release and final fencing check. The old block can attempt to persist before the coordinator's final check; the durable mutation must fence it if the scenario confirms that path. Couple checks and writes under the existing UnitOfWork rather than adding a second transaction owner.
4. Repair confirmed workflow/phase/settlement defects at the narrowest enforcing owner. Preserve requiredWrite ordering, original outputs/ledger and migrated-byte compare checks. Failed commit or retry exhaustion must propagate typed failure and cannot return success. Contradictory upsert is not idempotent merely because its SQL succeeds.
5. Audit worker and control lease instant admission, active/expired semantics, terminal heartbeat refusal, owner release and crash reconciliation. SQL lexical expiry and parsed Instant comparison must agree for admitted canonical UTC and supported legacy offset tokens. Inject clock/host facts; preserve observability and cooperative cancellation in reconciliation/heartbeat paths. A broad catch must not convert cancellation into a healthy candidate or successful action.
6. Audit whole-control JSON writes against simultaneous pause/completion and stale lease renewal. Keep generation/owner checks and lifecycle policy in their proper layers. Ensure abandoned state retains reason/time, does not complete steps, and does not leave mutation authority capable of reactivating that row. Record parent/child closure policy for subtask 2.
7. Define the fixed one-day standalone failure scenario. Retain finite expiry. If proven necessary, add owner-only renewal with explicit generation/revision semantics and scheduler failure diagnostics through existing ports/owners. Do not use polling to extend activity. Unknown or foreign-host process evidence cannot grant unsafe takeover or successful completion.
8. Repair stop's false-success branch only after tracing the complete refusal/error/exit path. Keep the persisted operator pause, require honest exit observation, preserve interruption/cancellation and record typed inspection/termination/timeout failures. Do not kill an unrelated PID to satisfy a stop request.
9. Add or extend the few production-boundary regressions below. Update contracts only for demonstrated requirements, with schema first, owner constants/keys/enums/failure codes and parity/compatibility admission. Document remaining external process limitations and any supported refusal.
10. Finish evidence_subtask_1.md with source citations, all AC mappings and A1-A12/G1-G7 checklist applicability/results. Mark authored reproductions and tests as unexecuted until validate records results. Hand off parent aggregate/projection cases to subtask 2 with exact finding IDs and dependencies.
