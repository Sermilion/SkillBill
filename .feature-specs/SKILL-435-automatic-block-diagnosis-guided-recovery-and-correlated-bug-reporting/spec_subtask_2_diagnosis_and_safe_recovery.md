# Subtask 2: evidence-based diagnosis and fenced guided recovery

## Scope

Build proposed BlockDiagnosisWorker and BlockRecoveryService with typed immutable inspectIncident, previewRecovery, recover and reconcilePending requests. Extend subtask 1's lifecycle with a bounded read-only evidence packet and a closed recovery catalog. Shared state is persisted through narrow incident ports; adapters never decide eligibility.

## Acceptance Criteria

1. Investigation produces a saved structured diagnosis from integrity-checked bounded causal evidence, distinguishing facts, inferences, unavailable evidence and unknown causes under enforced read-only authority.
2. A closed typed recovery catalog exposes prerequisite-aware previews with explicit effects and supports user initiation only for eligible actions, leaving operator-required causes with instructions.
3. Recovery admission revalidates the incident generation, exact saved target, prerequisites and live ownership under durable fencing so stale or concurrent requests cannot apply or launch twice.
4. Recovery applies supported changes atomically with their progress markers, verifies that the block cleared and resumes the exact saved goal/phase only after safe handoff and successor ownership are established.
5. Recovery interruption, failed apply/verification/resume and ambiguous launch acknowledgement preserve the original incident and durable action history so retries reconcile without repeating completed effects or bypassing limits.

## Evidence and diagnosis contract

Read relevant workflow/run records, accepted/rejected settlement, attempt ledger and carryover, original throwable/code and failed tool invocation only when retained, bounded neighboring output, retained instructions/briefings, rejected/producer output, repair checks, selected strategy/model, runtime version/build and allowlisted OS/provider facts. No whole DB scan, raw environment dump or private source upload. Missing, expired, oversized and integrity-invalid sources stay explicitly unavailable. Preserve producer generation, repair turn, agent and evidenceKey. Existing RejectedOutputDiagnosticService.inspect/readRaw performs cleanup and is unsuitable for read-only investigation; add verified read-only access reusing byte-count/SHA-256 checks via its repository. RequiredPhasePersistenceTest proves some audit briefings are ephemeral; do not fabricate them.

Separate repair inspection from GoalRunnerRepairCoordinator's current bindRepositoryIdentity write. Reuse apply=false checks only through that truly read-only seam. Distinguish INSPECTED from REPAIRED and evidence from model explanation. Use AgentRunLauncher.launch/resolveLaunchModel selection with a restricted evidence-only capability packet. A prompt saying read-only is insufficient. No arbitrary tools, user-project writes, blocked-state writes or execution based on log text/model suggestions. If an enforced read-only agent strategy is unavailable, use deterministic partial diagnosis and record unavailable_agent rather than broadening authority. Implementation confirms the provider capability; the safe fallback is fixed by this spec.

The saved diagnosis has summary, what happened, diagnosed/suspected cause, supporting references and source limits, confidence/uncertainty, observed/inferred/unknown distinction, responsibility category, user prerequisites, known workaround or explicit none-known, eligibility/action/effects, report state/link and telemetry availability. Categories are project/source, user environment/credentials/configuration, external provider/service, Skill Bill defect and unresolved. Hypothesis alone establishes neither defect nor recovery authority. Reuse subtask 1's time/text/turn/attempt budgets and schema validation. Secondary failures retain partial evidence and original block unchanged.

## Recovery catalog and transaction policy

Initial catalog uses proposed versioned typed actions `REPAIR_CONFIRMED_STALE_OWNER_AND_RESUME` and `RESUME_REPAIRED_CONTINUATION`. They wrap only existing proven repair/reopen/resume operations for confirmed-dead stale execution/child leases, stale blocked continuations and interrupted pauses tied to an actual incident, or deterministic repaired selection/upstream-output/review-base conditions. Each rule must establish the existing repair preconditions for that exact saved target; unsupported branches remain instructions. A normal pause by itself is never an incident or automatic-recovery offer. PHASE_OUTPUT_CONTRACT_INCOMPATIBLE remains operator-required. Missing credentials or user edits show instructions and a check-again path until verified. No reset, arbitrary SQL/shell, model-selected action, gate bypass, operator-decision override or attempt-budget reset.

Use GoalRunnerRepairCoordinator operations and WorkflowServiceBlockedPhaseRetry only behind incident admission. Current childWorkerLeaseLive returns false after an ownership-read failure; recovery must instead fail closed on unknown ownership. The retry path resets generic attempt_count, so preserve the effective accepted-attempt/failure budget through durable generation/ledger accounting; no extra attempts become available. Preserve mandates, checkpoints, completed work and SKILL-429 coordinator/carryover revisions.

Preview carries incident ID/revision/block generation, action/version, checked prerequisites, expected effects, exact target and expiring confirmation token. Default preview lifetime is 60 seconds; confirmation always rechecks state. Persist recovery ID, request idempotency key, expected revisions, selected DB file identity, process/lease ownership key, progress and effects before apply. Admission uses DatabaseSessionFactory.transactionFenced and compare-and-set; re-read workflow/attempt, branch/PR/worktree, current live owner and required operator decisions. Stale store/window/incident/attempt/branch and unknown ownership refuse without mutation. UI disabled state is only feedback, never authorization.

Couple applied markers and database effects in one transaction. Use WorkRunActions and saved WorkRunTarget/WorkRunLauncher scope, recorded arguments, selected agent and allowlisted environment. Goal resumes keep repo-root/no-live-output. Standalone uses its saved AgentHarness; monitor uses exact PR and owned worktree, never caller-checkout branch switching or issue-key-only relaunch. Crash after apply resumes the saved handoff without reapplying. Ambiguous spawn acknowledgement reconciles recorded process/lease key before retry; unknown stays pending/refused. A spawn Started result is not proof of resumed state. Observe intended successor accepted ownership before marking resumed. Verification failure or unsafe resume retains original incident and records failed/retryable/terminal action outcome independently of reporting.
