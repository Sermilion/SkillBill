# SKILL-435 subtask 2: structured diagnosis and evidence-based investigation

## Scope

Replace subtask 1's default `PARTIAL` investigator with an evidence-based one that writes a durable, structured diagnosis. The investigation reads bounded evidence from saved run records, classifies the cause deterministically from typed failure facts, optionally asks a read-only agent for suspected causes, and settles the incident with a visible account of every fallback.

This subtask covers intake paragraphs 2, 3 and the degradation part of 4, which belong to parent criterion AC-001. Recovery execution is subtask 3; the diagnosis here only proposes an action from the closed catalog. The bug-report state and link are joined from subtask 4's report record by subtask 5's projection, so this record stores neither.

Contract decision (preplan D3): the diagnosis is stored in relational tables validated by a domain `validation()` function, not as a YAML document, so no new YAML runtime contract is created and `block-incident-schema.yaml` stays at `0.2`. Every new wire string lives in `runtime-contracts`.

## Acceptance Criteria

1. The domain defines a structured, validated diagnosis record and its closed vocabularies in new files.
   New files under `runtime-domain/src/main/kotlin/skillbill/workflow/taskruntime/model/blockincident/` define `BlockIncidentDiagnosisRecord` with fields `occurrenceToken`, `revision`, `summary` (max 280 characters), `whatHappened` (max 2000), `cause` (max 2000, nullable), `certainty`, `uncertaintyNote` (max 1000, nullable), `responsibleCategory`, `evidence` (list of `BlockIncidentDiagnosisEvidence`, max 16), `prerequisites` (list of `BlockIncidentPrerequisite`, max 8), `proposedRecoveryAction`, `recoveryEffects` (max 1000, nullable), `noWorkaroundKnown`, `degradations` (set of `BlockIncidentDegradation`), `investigatorKind` and `completedAt`. `BlockIncident.kt` does not grow.
   Enums and members: `BlockIncidentCertainty {DIAGNOSED, SUSPECTED, UNKNOWN}`; `BlockIncidentResponsibleCategory {PROJECT_SOURCE, USER_ENVIRONMENT, EXTERNAL_SERVICE, SKILL_BILL_DEFECT, UNRESOLVED}`; `BlockIncidentPrerequisiteKind {CREDENTIALS_CONFIGURED, CONFIGURATION_FIXED, PROJECT_EDIT_COMPLETED, EXTERNAL_SERVICE_AVAILABLE}` with a `BlockIncidentPrerequisiteCheck {RUNTIME_CHECKABLE, USER_CONFIRMED}`; `BlockIncidentRecoveryAction {REOPEN_BLOCKED_PHASE, RETRY_AFTER_PREREQUISITE, NONE}`; `BlockIncidentDegradation {READ_ONLY_NOT_ENFORCED, AGENT_UNAVAILABLE, AGENT_TIMED_OUT, AGENT_OUTPUT_REJECTED, EVIDENCE_UNAVAILABLE, EVIDENCE_TRUNCATED, DEADLINE_EXCEEDED, NOT_PICKED_UP, CLAIM_TAKEN_OVER, SPOOL_IMPORTED}`; `BlockIncidentInvestigatorKind {DETERMINISTIC, DETERMINISTIC_WITH_AGENT}`.
   Each evidence item has `kind` (`WORKFLOW_STATE`, `PHASE_LEDGER`, `REJECTED_OUTPUT`, `PRODUCER_OUTPUT`, `ATTEMPT_HISTORY`, `RUNTIME_VERSION`, `PHASE_BRIEFING`, `ORIGINAL_FAILURE`), a copyable `reference` id, a `summary` of at most 512 characters, `sha256` and `trusted` (false for log text and model output).
   `validation()` returns typed violations when `certainty` is `DIAGNOSED` but no evidence item supports it, when `responsibleCategory` is `UNRESOLVED` but `certainty` is not `UNKNOWN`, when `proposedRecoveryAction` is `NONE` but `recoveryEffects` is set, or when a length cap is exceeded.
   Wire values for every enum member live in a new keys file under `runtime-contracts/.../contracts/workflow/identity/blockincident/`, as lowercase snake case of the member name.
   Persistence is criterion 2. Audit confirms by reading the new domain files and the keys file.
2. Diagnosis records persist durably with fenced writes, validated readback and retained history.
   A new append-only migration (next free version, expected 77) creates `block_incident_diagnoses` (occurrence token, revision, scalar fields, `degradations` as a sorted comma list of wire values, `completed_at`) with primary key `(occurrence_token, revision)`, plus `block_incident_diagnosis_evidence` and `block_incident_diagnosis_prerequisites` child tables keyed by `(occurrence_token, revision, ordinal)`. Rows are immutable after insert by trigger, following the migration 66 pattern. It registers desktop change-revision triggers on the parent table with the `addBlockIncidentRevisionTriggers` pattern, and bumps `DesktopReadSchema.VERSION` if that constant's existing rule requires it for new desktop-read tables (implement confirms the rule).
   `BlockIncidentRepository` gains `settleWithDiagnosis(token, ownerToken, ownerGeneration, diagnosis: BlockIncidentDiagnosis, record: BlockIncidentDiagnosisRecord, nextEligibleAt): Boolean`, which writes the record and settles the incident state in one statement group only while the caller still holds the claim, and returns false otherwise. It also gains `diagnoses(token): List<BlockIncidentDiagnosisRecord>` ordered by revision ascending, so history survives later revisions and resume.
   Readback runs `validation()`; a row that fails is quarantined with failure code `QUARANTINE`, matching the existing occurrence quarantine. `SqliteBlockIncidentRepository` delegates to a new `SqliteBlockIncidentDiagnosisStore` file so the 651-line repository file does not grow past its ceiling. `InMemoryBlockIncidentRepository` implements both methods.
   Audit confirms by reading the migration, the port methods, the sqlite store and the fixture.
3. A bounded, read-only evidence collector gathers investigation inputs from saved records only.
   A new `BlockIncidentEvidenceCollector` in `engine/diagnostics/block` reads, for the incident's workflow, attempt and phase: the workflow state through `unitOfWork.workflowStates`; the decoded phase ledger through the existing `FeatureTaskRuntimePhaseStateRecorder` ledger decoder; rejected and producer output through `RejectedOutputDiagnosticRepository.readProducerOutputExact` using the digests already on the occurrence's evidence references; prior attempts of the same phase; retained phase briefings when saved; the injected `skillbill.model.RuntimeVersion`; and the occurrence's original reason and failure code.
   Budgets: at most 16 items, 8 KiB per item and 64 KiB in total, matching the existing occurrence evidence limits. Truncated items keep their full `sha256` and add `EVIDENCE_TRUNCATED`; missing or unreadable sources add `EVIDENCE_UNAVAILABLE` and appear as an item whose summary names the missing source. Items read from logs or model output are marked `trusted = false`.
   The collector opens read-only transactions and calls no write method on any repository, workflow store or file in the user's project. It never reads `worktreePath` contents.
   Classification of the collected evidence is criterion 4. Audit confirms by reading the collector's reads, budget constants and the absence of write calls.
4. A deterministic classifier turns typed failure facts into a diagnosis, and unknown causes stay unknown.
   A new pure object `BlockIncidentClassifier` in `runtime-domain` maps the occurrence's `origin`, `failureCode`, `failureDisposition` and evidence kinds to a draft record. `failureDisposition` `needs_user_action` maps to `USER_ENVIRONMENT` with `certainty` `DIAGNOSED` and the matching prerequisite when the failure code names credentials or configuration. `non_retryable_policy_conflict` and `POLICY_BLOCKED` or `DEPENDENCIES_BLOCKED` goal stops map to `USER_ENVIRONMENT` with prerequisite `CONFIGURATION_FIXED`. Provider and network failure codes map to `EXTERNAL_SERVICE`. `invalid_output` and `process_failure` with runtime-side evidence map to `SKILL_BILL_DEFECT` with `certainty` `SUSPECTED`. Quality-gate and acceptance failures on project code map to `PROJECT_SOURCE`. Anything else maps to `UNRESOLVED` with `certainty` `UNKNOWN`. Implement lists the exact failure-code literals in the mapping table from `BlockIncidentFailureCode` and the existing feature-task failure codes it can read.
   The classifier proposes `REOPEN_BLOCKED_PHASE` only for a blocked feature-task phase whose disposition is `retryable` or `needs_user_action`, `RETRY_AFTER_PREREQUISITE` only when at least one prerequisite exists, and `NONE` otherwise, with `recoveryEffects` describing what the action changes. When no action and no prerequisite apply, it sets `noWorkaroundKnown = true`.
   `summary` and `whatHappened` are composed from typed facts, not by echoing the raw reason; the raw reason appears only as the `ORIGINAL_FAILURE` evidence item.
   Agent enrichment is criterion 5. Audit confirms by reading the mapping table and the unknown fallback.
5. The investigator optionally runs one bounded read-only agent pass, records every degradation, and settles the incident through the diagnosis record.
   A new `EvidenceBlockIncidentInvestigator` replaces subtask 1's default `BlockIncidentInvestigator` binding in `RuntimeComponent`. It runs the collector and classifier, then, when the workflow's recorded agent resolves through `AgentRunLauncher.resolveLaunchModel`, launches one `SkillRunRequest` with `readOnlyPhase = true`, a `promptOverride` holding only the collected evidence summaries and the draft record, a `timeout` of the remaining run deadline minus 30 seconds, and no `additionalWritableDirectories`.
   Agent output is parsed as untrusted JSON with fields `suspected_cause` and `evidence_refs`. It can only add a cause with `certainty` `SUSPECTED` that cites collected evidence references; output that fails to parse, cites unknown references or tries to change category, prerequisites or recovery action is discarded with `AGENT_OUTPUT_REJECTED`. No output is executed.
   No resolvable agent adds `AGENT_UNAVAILABLE` and settles `UNAVAILABLE_AGENT`. An agent timeout adds `AGENT_TIMED_OUT` and settles `PARTIAL`. Because the launcher does not report provider enforcement of read-only mode, every agent pass adds `READ_ONLY_NOT_ENFORCED` and settles `PARTIAL` rather than `COMPLETE`; implement confirms whether `AgentRunLaunchOutcome` carries an enforcement fact and settles `COMPLETE` only when it says enforced. Without an agent pass, a record with no degradations settles `COMPLETE`. The worker adds `CLAIM_TAKEN_OVER`, `SPOOL_IMPORTED` or `NOT_PICKED_UP` when those happened. `settleWithDiagnosis` returning false leaves the claim to expire and settles nothing.
   Audit confirms by reading the investigator, its launch request fields, the output parser and the settle mapping.

## Test Obligations

1. T2.1 evidence uncertainty and classification. A block with failure disposition `invalid_output` and a rejected-output reference yields `SKILL_BILL_DEFECT` / `SUSPECTED`; a block with an unmapped failure code yields `UNRESOLVED` / `UNKNOWN` with `noWorkaroundKnown`; a `DIAGNOSED` record with no supporting evidence fails `validation()`. Realistic bug: an unknown cause gets labelled as a confident category.
2. T2.2 diagnosis failure. With no resolvable agent the incident settles `UNAVAILABLE_AGENT` with the deterministic record saved; with an agent that times out it settles `PARTIAL` with `AGENT_TIMED_OUT`; agent output naming an evidence reference that was not collected is rejected. Realistic bug: model output overrides the typed classification or a failed agent pass loses the deterministic diagnosis.
3. T2.3 persistence. In `SqliteBlockIncidentRepositoryTest`, `settleWithDiagnosis` from a stale owner returns false and writes no row, and two revisions read back in order. Realistic bug: a taken-over worker overwrites the new owner's diagnosis.
4. Migration upgrade evidence in `DatabaseMigrationsTest` from the subtask 1 version, preserving existing incident rows.

### Task 4. Evidence collector (AC 3)

- New `engine/BlockIncidentEvidenceCollector.kt` (`internal class`, `@Inject` with `RuntimeVersion` and the ledger decoder dependency). Signature: `collect(unitOfWork: UnitOfWork, incident: BlockIncident): CollectedEvidence`, where `CollectedEvidence(items: List<BlockIncidentDiagnosisEvidence>, degradations: Set<BlockIncidentDegradation>, contents: Map<String, String>)`. `contents` holds the bounded text per reference for the agent prompt and never leaves the engine.
- Reads, in this order so the budget keeps the most useful items: `ORIGINAL_FAILURE` from the occurrence's reason and failure code (always present, `trusted = false` because reason text can carry log output); `WORKFLOW_STATE` via `unitOfWork.workflowStates`; `PHASE_LEDGER` via the existing `FeatureTaskRuntimePhaseStateRecorder` ledger decoder (`decodePhaseLedger`); `REJECTED_OUTPUT` and `PRODUCER_OUTPUT` via `unitOfWork` `RejectedOutputDiagnosticRepository.readProducerOutputExact(workflowId, phaseId, attempt, agentId, generation, repairTurn, expectedDigest, expectedByteSize)` using the digest and size on the occurrence's evidence references, both `trusted = false`; `ATTEMPT_HISTORY` for earlier attempts of the same phase from the ledger; `PHASE_BRIEFING` when the workflow artifacts retain one; `RUNTIME_VERSION` from the injected `skillbill.model.RuntimeVersion`.
- Assumptions for implement to confirm: the ledger decoder is reachable from `engine/diagnostics/block` without a dependency cycle (if not, extract the pure decode function to a shared internal helper rather than duplicating it); `agentId` and `repairTurn` for `readProducerOutputExact` are on the evidence reference or the ledger entry; phase briefings are stored as workflow artifacts (if not saved anywhere, the collector emits an `EVIDENCE_UNAVAILABLE` item for `PHASE_BRIEFING` and moves on).
- Budget constants in the collector companion: `MAX_ITEMS = 16`, `MAX_ITEM_BYTES = 8 * 1024`, `MAX_TOTAL_BYTES = 64 * 1024`. Reuse the existing occurrence limit constants if they are already public; do not define a second copy with different values. Truncation cuts on a UTF-8 boundary, keeps the full-content `sha256`, and adds `EVIDENCE_TRUNCATED`. A missing source, a `null` from `readProducerOutputExact`, a digest mismatch or a read exception adds `EVIDENCE_UNAVAILABLE` and an item whose summary names the source, with an empty-content sha256.
- Goal-level and standalone incidents with `NOT_APPLICABLE` phase fields skip phase reads and record only the sources that apply. That is not a degradation.
- Constraints: the caller opens the transaction read-only (Task 6). The collector calls no write method on any repository, never reads files under `worktreePath` or the repository root, and does not touch the network.

### Task 5. Deterministic classifier (AC 4)

- New `domain/BlockIncidentClassifier.kt` (pure `object`) with `classify(occurrence: BlockIncidentOccurrence, evidence: List<BlockIncidentDiagnosisEvidence>, degradations: Set<BlockIncidentDegradation>, completedAt): BlockIncidentDiagnosisRecord` returning a draft with `revision = 0`; the investigator stamps the revision. The mapping table lives in a second file `domain/BlockIncidentClassificationRules.kt` as an ordered list of rules so the table can be read and audited on its own.
- Rule order (first match wins):
  1. Disposition `needs_user_action`: `USER_ENVIRONMENT`, `DIAGNOSED`, prerequisite `CREDENTIALS_CONFIGURED` when the failure code names auth or credentials, `CONFIGURATION_FIXED` when it names configuration or settings, otherwise no prerequisite and certainty `SUSPECTED`.
  2. Disposition `non_retryable_policy_conflict`, or a goal-block reason of `POLICY_BLOCKED` or `DEPENDENCIES_BLOCKED`: `USER_ENVIRONMENT`, `DIAGNOSED`, prerequisite `CONFIGURATION_FIXED` (`USER_CONFIRMED`).
  3. Provider and network failure codes: `EXTERNAL_SERVICE`, `DIAGNOSED`, prerequisite `EXTERNAL_SERVICE_AVAILABLE` (`RUNTIME_CHECKABLE` only if subtask 3 can probe it; default `USER_CONFIRMED`).
  4. `invalid_output` or `process_failure` with a `REJECTED_OUTPUT`, `PRODUCER_OUTPUT` or runtime-side evidence item: `SKILL_BILL_DEFECT`, `SUSPECTED`.
  5. Quality-gate and acceptance failures (including `budget_blocked` from acceptance repair): `PROJECT_SOURCE`, `DIAGNOSED`, prerequisite `PROJECT_EDIT_COMPLETED` (`USER_CONFIRMED`).
  6. Anything else: `UNRESOLVED`, `UNKNOWN`, `uncertaintyNote` naming the unmapped code.
- Implement replaces "names auth", "provider and network" and "quality-gate and acceptance" with the exact failure-code literals from `BlockIncidentFailureCode` and the feature-task failure codes and dispositions the occurrence can carry, referenced through their contract constants, and lists them in a KDoc table on the rules file. Assumption: how a goal block records `POLICY_BLOCKED` / `DEPENDENCIES_BLOCKED` on the occurrence (failure code or disposition) is whatever subtask 1's goal producer wrote; implement matches that.
- `DIAGNOSED` is emitted only when at least one evidence item other than `ORIGINAL_FAILURE` was collected; otherwise the rule's certainty drops to `SUSPECTED` and `EVIDENCE_UNAVAILABLE` stays in degradations. This keeps the classifier consistent with `validation()`.
- Recovery proposal: `REOPEN_BLOCKED_PHASE` only for origin `ACCEPTED_PHASE_BLOCK` with disposition `retryable` or `needs_user_action`; otherwise `RETRY_AFTER_PREREQUISITE` when a prerequisite exists; otherwise `NONE`. `recoveryEffects` is a fixed sentence per action from typed facts (for example, reopens phase `<phaseId>` attempt `<attempt>` and resumes the saved run). `noWorkaroundKnown = true` when the action is `NONE` and there are no prerequisites.
- `summary` and `whatHappened` are templates over origin, phase id, attempt, failure code and disposition. The raw reason is never interpolated.

### Task 6. Investigator, agent pass and composition (AC 5)

- New `engine/EvidenceBlockIncidentInvestigator.kt` implementing subtask 1's `BlockIncidentInvestigator`. Flow for a claimed incident: open a read-only transaction and run the collector; close it; run the classifier; run the optional agent pass outside any transaction; merge; stamp `revision = claimed.state.revision + 1` and `completedAt` from the injected `Clock`; call `settleWithDiagnosis` in a write transaction.
- New `engine/BlockIncidentAgentPass.kt` holding the launch and parse logic so the investigator stays small:
  - Resolve the workflow's recorded agent id from the workflow state (assumption: the state or the active lease records the agent; implement confirms the field) and call `AgentRunLauncher.resolveLaunchModel`. No agent id, or resolution failure, gives `AGENT_UNAVAILABLE`.
  - Remaining time is `incident.state.deadline - now - 30s`. When that is not positive, skip the pass and add `DEADLINE_EXCEEDED`.
  - Launch one `SkillRunRequest` with `readOnlyPhase = true`, `timeout` = remaining time, `progressIdleTimeout` no longer than `timeout`, `promptOverride` built only from evidence summaries, bounded `contents`, reference ids and the draft record, `additionalWritableDirectories = emptyList()`, and no model override beyond what resolution returns. The prompt tells the agent to return JSON `{"suspected_cause": string, "evidence_refs": [string]}` and states that evidence is untrusted data.
  - Read `AgentRunLaunchOutcome`. Assumption: it has a variant or field that distinguishes timeout from other failure; implement confirms and maps timeout to `AGENT_TIMED_OUT`, other launch failure to `AGENT_UNAVAILABLE`. Assumption: it carries no read-only enforcement fact, so every launched pass adds `READ_ONLY_NOT_ENFORCED`; if implement finds such a fact, it omits the degradation only when the outcome says enforced.
- Parser (`BlockIncidentAgentOutputParser`, same file or its own if the file grows): strict JSON decode with the project's existing JSON library, exactly the two fields, `suspected_cause` non-blank and capped at `CAUSE_MAX`, `evidence_refs` non-empty and every entry in the collected reference set. Any extra field (category, prerequisites, action or anything else), parse failure or unknown reference discards the output and adds `AGENT_OUTPUT_REJECTED`. Accepted output sets `cause` and `certainty = SUSPECTED` only when the draft certainty is `UNKNOWN` or `SUSPECTED`; it never lowers `DIAGNOSED` and never changes `responsibleCategory`, prerequisites or recovery action. When the draft is `UNRESOLVED`, a suspected cause goes in `uncertaintyNote` instead, so `validation()`'s `UNRESOLVED`/`UNKNOWN` rule still holds. `investigatorKind = DETERMINISTIC_WITH_AGENT` whenever a launch happened.
- Settle mapping, first match wins: `AGENT_UNAVAILABLE` gives `UNAVAILABLE_AGENT`; `DEADLINE_EXCEEDED` gives `TIMED_OUT` only if the incident deadline has passed (the transition refuses it otherwise), else `PARTIAL`; any other degradation (including `AGENT_TIMED_OUT`, `READ_ONLY_NOT_ENFORCED`, `AGENT_OUTPUT_REJECTED`, evidence degradations) gives `PARTIAL`; none gives `COMPLETE`. `nextEligibleAt` is `null` for terminal states. A `false` return from `settleWithDiagnosis` is logged through `RuntimeDiagnostics` as a warning and nothing else happens; the claim expires and subtask 1's takeover picks it up.
- `CLAIM_TAKEN_OVER`, `SPOOL_IMPORTED` and `NOT_PICKED_UP`: assumption that subtask 1's worker passes these facts to the investigator (on the claim context or the incident aliases). Implement extends the investigator input with a `workerDegradations: Set<BlockIncidentDegradation>` parameter if subtask 1's seam does not already carry them, changing only the seam signature and the worker call site.
