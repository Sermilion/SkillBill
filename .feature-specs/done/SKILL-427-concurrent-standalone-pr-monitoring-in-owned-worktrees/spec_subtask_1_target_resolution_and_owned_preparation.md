# SKILL-427 subtask 1 - target resolution and owned execution preparation

## Scope

Implement the typed target selector/resolution boundary, monitor-specific admission and owned-worktree preparation/cleanup, and strict persisted ownership contract. This is the first of three required same-branch subtasks. It delivers the preparation capability and its lifecycle proof; public standalone route activation waits for the accepted execution and status/control work in subtasks 2 and 3.

Primary ownership is runtime-ports/.../ports/monitor and area-owned models, runtime-engine/.../featuretask/phaserun/monitor, runtime-infra/workflow/.../monitor, the ownership schema under orchestration/contracts, and composition wiring in runtime-core. Exact names are proposed. Do not broaden generic Git worktree interfaces into a general manager.

## Acceptance Criteria

1. A purpose-built typed target port and selector policy represent URL, exact issue-key, and omitted current-branch intake. Resolution returns exact immutable host/base-repository/PR identity, URL, actual head repository/ref/SHA/fetch/push endpoints, actual base repository/ref/SHA, state, and writability evidence, or a typed terminal/refusal/failure result. Legacy identity/check services remain unchanged.
2. URL resolution never substitutes the caller PR; repository mismatch, malformed/missing/ambiguous/incomplete targets refuse before checkout/publication. Issue lookup is tracker-free, token-exact, completely paginated, and uniquely selects an open match or applies the specified unique terminal policy. Omitted intake with no open PR completes usefully; merged explicit completes identified; closed-unmerged explicit blocks identified.
3. Admission keys the canonical common Git directory and canonical target PR, holds an atomic cross-process lock, and reports an existing live owner without superseding or signalling it. Stable lock-file identity, owner token and increasing generation fence metadata/resource changes and release across linked worktrees and same-JVM overlap.
4. Prepared resources use invocation-specific fetch refs and local branch/worktree at the verified published SHA, including when the actual head branch is already checked out elsewhere. Caller branch refs, HEAD, index, pending files, remote configuration, and operator-owned worktrees remain untouched. Preparation exposes typed execution context and cleanup ownership without services in request facts.
5. Cleanup ownership begins immediately after admission and handles partial setup, cancellation, and runtime exit. It removes only verified owned clean work with no unpublished commit, retains dirty/untracked/unpushed/uncertain work and refs with exact reason/path, fences release, preserves the primary error, and records independent cleanup failures. There is no fallback checkout.
6. The versioned ownership schema, Kotlin contract version/keys, strict parse seams, typed failure codes, parity/rejection coverage, and lifecycle diagnostics exist. Explicit stale recovery requires the expected owner token, acquirable lock and positive exact-process death evidence; it refuses live/unknown owners and retained unfinished repairs.
7. T1 and T2 boundary tests exist beside owned behavior, including exact/fork/ambiguous/missing targets, checked-out head isolation, linked-worktree duplicate admission, stale-token fencing, setup/cancellation failures, and safe cleanup/retention. They use controlled Git/fake PR services and do not depend on live PR mutation.

## Implementation Details

1. Read the applicable governing architecture, runtime command, code and source-generation documents during implementation. Use A1-A8, A10-A12, P2 and section 5 to place typed policy in engine/domain, effect ports in runtime-ports, Git/GitHub/filesystem/lock implementations in runtime-infra and construction in runtime-core. A2/A6 require one canonical target-key and fence derivation; A3 excludes service bags from immutable context; A4/A12 require typed results; A7/A8 require explicit failures, cancellation and injected host/time/process effects. Apply A9 and G1-G7 without relaxing guards, baselines or exemptions. Narrow visibility under A11, tests beside owners under A10, and no prohibited Kotlin comments.
2. Define area-owned selector, canonical target identity, resolved target, expected-head, repository context, acquisition/cleanup outcomes and opaque fence values. Suggested ports separate target resolution/observation from resource I/O because they have different effects and failure boundaries. Let engine and adapters consume the port DTOs; avoid raw maps, vendor JSON and forwarding-only wrappers. Resolve repository primary root via Git common-dir metadata, use its existing identity owner for status grouping, and carry caller root and execution root separately.
3. Implement read-only GitHub target lookup with explicit repository/number on every lookup. URL parsing accepts supported GitHub host PR URLs with exact repo/number, no credentials or arbitrary transport endpoints. Require caller base-repository match; permit fork heads with independently validated endpoints. Reject unsupported/incomplete data. Resolve issue keys over complete paginated title/body/head metadata using complete key tokens. Prefer exactly one open match; ambiguity reports candidate URLs; absent open matches use exactly one terminal candidate or block ambiguity/absence. Omitted branch lookup includes head-repository identity to avoid fork branch-name collisions, completes only for no open candidate, and otherwise requires uniqueness. Explicit merged completes, explicit closed-unmerged blocks, neither acquires resources. Never invoke a tracker. Do not modify GhPullRequestIdentityLookup or legacy checks lookup to implement this feature.
4. Add standalone-monitor-ownership-schema.yaml with contract_version 1.0 as a Draft 2020-12 YAML contract. Define required target tuple, owner invocation/token/generation, host/PID/process-start identity, caller/primary root, common directory, optional execution path and owned refs during acquisition, pinned/last-published SHAs, lifecycle state acquiring/prepared/retained/released, timestamps, and optional typed retention/failure detail. Require state-coherent tuples and forbid arbitrary extra fields. Add the owning Kotlin *_CONTRACT_VERSION, centralized owner keys and RuntimeFailureCode entries with SkillBillRuntimeException at every parse seam. Add parity and acceptance/rejection tests, including legacy/unknown version, partial target/resource tuple, malformed fence and incoherent retained state. Do not add these keys to runtime-contracts unless its second consumer/port ownership requires it.
5. In the monitor adapter, derive <common-git-dir>/skill-bill/standalone-monitor/<target-key-hash>. Hold a stable file lock for the entire invocation; never unlink it. Treat cross-process contention and OverlappingFileLockException as duplicate refusal with recorded owner/target/path. Write metadata atomically while locked. Under engine orchestration, admission success immediately creates the sole lifecycle owner before fetch or path creation. Persist ownership intent before effects so a crash between creation and prepared metadata remains diagnosable. Every metadata mutation, cleanup and release verifies owner token/generation. Keep released tombstones/generation history. Do not use status leases as the admission lock.
6. Define a typed expected-stale-owner token input for future CLI --recover-stale-owner <owner-token>. Under an acquirable lock compare the stored token and process-start identity. Recover only when the exact process is positively dead on the verifiable host. Expired timestamps, different/unknown hosts, lock contention, and unknown PID identity are refusals. Never kill a process. Retained unpublished/dirty work blocks fresh setup and reports its path. With safe clean stale state, advance generation, validate ownership, remove only owned safe remnants and prepare new resources. Corrupt metadata blocks with path; any established-policy quarantine/regeneration must retain resource evidence and never bypass live ownership.
7. Specify orchestration order as allocate invocation, resolve target, resolve common-dir/original identity, acquire ownership, establish cleanup, fetch explicit target head into an invocation-owned ref without FETCH_HEAD/shared remote mutations, verify object identity, fetch/verify pinned actual base, create unique owned local branch/worktree, validate mapping, then return prepared typed context. Future run facts/status/branch capture must occur after this return. Create worktrees under an invocation-specific private monitor worktree directory, outside caller files. Ref/path containment and symlink/ownership checks precede removal. Git operations use explicit endpoints and no shared remote/config rewrites. A target branch already checked out elsewhere needs no checkout override because the owned branch has a separate name.
8. Make cleanup structured and bounded. Stop/drain owned child work before inspecting/removing execution resources. Check tracked/index/untracked state and explicit remote publication evidence. Clean removal requires certainty that every owned commit is published or the worktree is still the exact untouched baseline. Dirt, untracked repair files, unpushed/uncertain commits, unknown ownership, remote-comparison failure and cleanup failure retain worktree and refs with a precise disposition. Do not force-remove. On failure before a worktree exists, release only the matching fence and safely remove any proven owned partial refs. Preserve primary failure and emit secondary cleanup diagnostics. Provide bounded shutdown fallback integration for later execution; SIGKILL becomes stale recovery, not guaranteed cleanup.
9. Wire real/fake dependencies at composition/test construction seams, without default no-op ports. Do not activate the public monitor route, rewrite legacy definitions, or add standalone branches to preserved strategies. The next subtask consumes this typed preparation capability before run initialization.
