Read applicable repository and nested instructions, formatter and linter configuration, package or build scripts, wrappers, hooks, CI requirements, and project-selected tool versions. Resolve applicability by the intended files, their languages, and modules using the project's own rules. Execute safe applicable commands that preserve owned input and rewrite scope and avoid compilation, builds, tests, and full checks. Repair their in-scope findings and rerun them in the same authoring session. Inspect resulting changes for scope compliance. Broad formatting followed by reverting collateral edits is not an acceptable scope strategy.

For missing tools, ambiguous rules, unsafe bootstrap behavior, compilation-coupled analysis, or commands that would rewrite unrelated files, record nonexecution and the concrete reason. Preserve unrelated dirt. Report out-of-scope findings without expanding repair admission. Do not weaken rules, add suppressions or baselines, skip required tests, replace project-selected tools or versions, or call deferred work passed. An unavailable authoring check can be deferred to its existing phase owner; known repairable in-scope findings cannot be declared resolved through deferral.

Use existing retained evidence locations rather than introducing wire fields. Do not create fake findings or repair entries for command deferrals. Inline review emits compact evidence before its findings register and final verdict; InlineReviewResultDecoder preserves that prose and InlineReviewEnvelope retains its leading summary up to the existing 2,000-character cap. Keep evidence within that retained budget, and report any evidence limitation explicitly rather than implying complete retention. A record identifies configuration sources and selected version, exact candidate command and working directory, owned scope and safety basis, actual outcome or nonexecution reason, remaining findings, and the existing owning phase. Keep records bounded and free of raw transcripts or diff hunks. Preserve existing diagnostics for runtime failures and degradation; do not add an agent-authored telemetry protocol.

Validation currently projects the plan and current repository scope, not all authoring reports. Preserve that boundary. Put the discovery and deferred-check responsibilities in the governed validation strategy and retain session evidence for inspection, without claiming automatic receipt delivery to validate or widening handoff allowlists. Validation must independently discover applicable checks and must not treat an authoring report as gate clearance.

Reconcile conflicting wording across the complete composed prompts. Remove the audit inspection compile exception from AcceptanceAuditPromptSections.kt. Narrow AuditImplementFixPromptSections' blanket command-execution prohibition to the actual owned categories. Correct ImplementationPromptSections' compilation-to-validate wording to preserve build ownership and permit safe scoped authoring checks without granting full validation authority. Review InlineReviewDirective and FeatureTaskRuntimePhasePromptGateProofDirectives for the same distinction. Preserve audit's production-only repair admission, simplify's owned-path boundary, review's finding scope, and all existing retry, continuation, checkpoint, settlement, and gate behavior.

Extend existing prompt, launch-capture, review-envelope, and slotbaseline tests where possible. Inspect the actual captured direct inline review launch, not only its unused shared-composer prompt. Add a synthetic non-Kotlin context with root and nested instructions, mixed languages, module-specific rules, project-selected versions, safe scoped commands, compilation-coupled analysis, an unavailable tool, and an unrelated-file sentinel.
