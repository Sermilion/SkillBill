# SKILL-442 subtask 5 - goal assessment stage, assessors, and verifier

## Scope

Parent criterion AC-005, part 1 of 3: the phase ids, tiers, slot, and skeleton; the durable assessment record; the assessor input assembly and assessor runs; and the verifier gate with fix-set selection. It ends with a `GoalRunnerAssessmentGate` that can run one assessed and verified round. Subtask 6 calls it from goal finalization and adds the fix loop. Subtask 7 adds the PR, status, and desktop surfaces. Subtask 8 adds telemetry.

Shared decisions restated: assessors run sequentially. Assessor and verifier output travel as parsed prose lines in the existing `feature_task_phase_complete` value. An assessor or verifier that fails, or whose output has no parseable line, gets no re-ask: the runtime records a `RuntimeDiagnosticsBestEffortWarning`, marks that run `failed` or `malformed`, and the round continues with the outputs it has. Nothing in this stage blocks the goal.

Line grammar. Assessors emit `Finding: <Blocker|Major|Minor> <path>:<line> scenario <concrete failure scenario>` and `Test value: <test path>:<line> guards <path>:<line> reason <why it cannot fail>`. The cross-subtask assessor also emits `Scenario <IS-NNN>: <holds|broken> evidence <citations>` and `Regression <TR-NNN>: <restored|not_restored> evidence <citations>`, and reports broken scenarios and chained defects as `Finding:` lines. The verifier emits `Verify <GA-NNN>: <confirmed|refuted> evidence <citations>`. `<citations>` is a comma-separated `path:line` list.

   `PhaseStrategyLookup` registers a read-only strategy for `goal_assessment`. If the lookup requires a strategy for every slot step, the slot lists only `goal_assessment` here and subtask 6 adds `goal_assessment_fix` with its strategy. The phase-output envelope's prose-phase enum stays unchanged, as it does for `qa_fix`.
   Agents settle through the MCP tools, whose `phase_id` enum comes from `orchestration/contracts/telemetry-event-schema.yaml` (the `feature_task_phase_complete` and `feature_task_phase_block` event definitions, contract `1.12.0`). Both enums gain `goal_assessment` and `goal_assessment_fix`, and that schema's `contract_version` and its Kotlin constant move forward per its versioning rule, so `mcp__skill-bill__feature_task_phase_complete` accepts the new phase ids.
   Audit confirms it by reading the phase ids, tier map, slot, skeleton, strategy registration, and the two telemetry schema enums.
2. A governed assessment record survives resume.
   A Draft 2020-12 contract `orchestration/contracts/goal-assessment-record-schema.yaml` requires `contract_version` (const `"0.1"`), `issue_key`, `rounds`, `exit_reason`, and `open_finding_refs`. `exit_reason` is null or one of `converged`, `round_cap`, `persistent_finding`, `assessment_unavailable`, `skipped_no_changes`.
   Each round requires `round` (1 to 3), `head_sha`, `scope_files` (empty means the whole goal), `assessor_runs` (`{role: subtask|cross_subtask|verifier, subtask_id: integer or null, status: completed|failed|malformed}`), `findings`, `scenarios` (`{scenario_ref, verdict: holds|broken, evidence}`), `regressions` (`{regression_ref, state: restored|not_restored, evidence}`), and `fix` (null, or `{status: completed|no_change|failed|not_run, changed_files, commit_sha, validation: passed|failed|not_run}`).
   Each finding requires `finding_ref` (`^GA-[0-9]{3}$`, unique across rounds), `kind` (`defect` or `test_value`), `severity` (the existing review severity tokens for Blocker, Major, Minor), `path`, `line`, `failure_scenario`, `guarded_ref` (null for defects), `subtask_id` (null for cross-subtask), `origin_round`, `verification` (`confirmed`, `refuted`, `unverified`, `not_required`), `verification_evidence`, `fix_rounds_survived` (integer from 0), `disposition` (`fix` or `pr_only`), and `state` (`open`, `fixed`, `refuted`).
   `runtime-contracts` gains `GOAL_ASSESSMENT_RECORD_CONTRACT_VERSION = "0.1"` and a payload-keys object. `FeatureTaskRuntimeFailureCode` gains `INVALID_GOAL_ASSESSMENT_RECORD`, registered in its classification list and `BlockIncidentClassificationRule`. A runtime-domain model and codec loud-fail on schema violations.
   This criterion does not persist the record (criterion 3). Audit confirms it by reading the schema, constant, keys, failure code, and codec.
3. Assessors see the specs and commits, never the pipeline's verdicts.
   A new assembler in the goal runner (a new package beside `goalrunner/qa`) builds assessor input only from: the parent spec text, every subtask spec text (from the manifest's `subtasks[].spec_path`), the parent's `## Interaction Scenarios` and `## Transitional Regressions` parsed with subtask 1's parser (an unparseable or absent section is passed as absent), each subtask's commit range (the previous subtask's commit, or the merge base with the base branch, to that subtask's recorded commit sha, with skipped subtasks marked as having no commit), and the feature branch head sha. It never reads audit, review, validate, or QA outputs, receipts, repair state, or acceptance states. The `goal_assessment` strategy declares no upstream phase projections.
   For round 1 the gate runs one read-only `goal_assessment` invocation per subtask with a commit, then one cross-subtask invocation, sequentially through `phaseRunEntry.runForGoal` on `SkeletonDefinition.GOAL_ASSESSMENT`. The cross-subtask invocation also runs when the parent has neither section, to look for defects that chain across subtasks. The prompt, a few sentences, says to judge each criterion against its spec at the branch head rather than at the subtask commit, to report only confirmed defects with a concrete failure scenario, to report tests that cannot fail with what they guard, and to end with the Scope grammar.
   The runtime parses the lines, assigns `GA-NNN` refs in order, and records findings, scenarios, regressions, and run statuses. `GoalRunnerWorkflowOutcomeStore` gains record and read operations for the criterion 2 record, next to `recordedGoalQaOutcome`. The gate writes the record after every assessor run and after verification, and on re-entry skips runs the stored record already holds. Audit confirms it by reading the assembler, its inputs, the invocation order, the parser, and the store calls.
4. A verifier confirms or refutes every Blocker and Major before any fix.
   After the assessors, the gate runs one separate read-only `goal_assessment` invocation in verifier role. It receives every Blocker and Major of the round with ref, path, line, and failure scenario, plus the same spec inputs as criterion 3 and no pipeline verdicts. It re-reads each finding at the branch head. A `Verify` line sets `verification` and `verification_evidence`. A finding with no line, or every finding when the verifier fails or is malformed, stays `unverified`. Minors and test-value findings get `not_required`.
   Fix-set selection sets `disposition: fix` on confirmed Blockers and Majors, and on Minors and test-value findings whose `path` equals the path of a confirmed finding. Every other finding, including unverified and refuted ones, gets `pr_only`. Refuted findings get `state: refuted`. `not_restored` regressions join the fix set.
   The gate is an interface `GoalRunnerAssessmentGate` (KDoc allowed on the interface) with a default implementation. It returns the round's record and fix set and never throws for an assessor, verifier, or parse failure. When every assessor run fails or is malformed, it reports `assessment_unavailable`. Audit confirms it by reading the verifier input, the verdict application, and the selection rules.
