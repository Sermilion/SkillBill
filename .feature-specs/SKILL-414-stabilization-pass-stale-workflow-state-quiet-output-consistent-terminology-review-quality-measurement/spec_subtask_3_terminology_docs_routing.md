## Acceptance Criteria

1. `README.md` has a `Glossary` section defining goal, workflow, subtask, phase, slot, step, operation, pack, lane and add-on. It names all 11 slot ids and the standalone phase ids exactly as declared in `PhaseSlot.kt` and `SkeletonDefinition.kt`, and states that `verify` is an operation. `docs/getting-started.md` links to it.
2. `README.md` lists all 11 slots, states that `phase:review` runs `standalone_review`, refers to `write_history` as a slot, and shows update-check as `skill-bill operation update-check`.
3. No file in `README.md`, `docs/` or `skills/skill-bill/content.md` calls `verify` a phase, names `bill-feature-verify` as a current command, describes nine phase slots, or presents `skill-bill code-review` as the driver of `phase review`.
4. `skills/skill-bill/content.md` documents review mode only as `mode:inline|delegated`, with omission meaning inline. It has a single `Review arguments` section using `target:<value>` syntax, no `Invoke the driver` section, a provider-neutral Rehydrate section, no duplicate `Routing` heading, and a sentence naming `orchestration/skill-classes/feature-launch-warning.yaml`.
5. The `SkillBillCommand` root description no longer describes review import as the CLI's purpose. `verify-stats` help no longer mentions `bill-feature-verify`. `PhaseCommand` help lists `mode:inline|delegated`.
6. Root help no longer lists a top-level `update-check`, and `skill-bill update-check` still reaches the update-check operation through an alias or a hidden command.
7. `routeIntake` prepends `goal` only for first tokens matched by a shared predicate in `runtime-contracts`: issue-key prefix, URL, or spec path. It normalizes `phase:<name>` and `operation:<name>` into two tokens and passes any other input through unchanged.
8. `PhaseInvocationParser` rejects `verify` and `phase:verify` with a message naming `skill-bill operation verify`.
9. Runtime-cli tests assert all of the following:
   - `phse review` produces an unknown-command error and does not reach goal intake.
   - `APP-123 Add CSV export` routes to goal.
   - `phase:review` routes to `phase review`.
   - `phase verify` fails with the operation hint.
10. A runtime-contracts test asserts the goal-intake predicate accepts an issue key, a `KEY-feature-slug` name, a URL and a `.feature-specs/` path, and rejects a plain word such as `phse`.
11. Tests or fixtures that pin the edited README, help or dispatcher text match the edited text.
