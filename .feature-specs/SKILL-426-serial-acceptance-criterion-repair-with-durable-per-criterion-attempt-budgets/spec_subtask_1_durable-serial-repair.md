## Acceptance Criteria

1. AC-001. Domain state and schema admission preserve canonical/original AC identities and catalog/spec/workflow/subtask/repository/execution/phase/attempt/checkpoint bindings. Initial discovery admits explicit source/validation dispositions and a dependency-provenance graph. Deterministic topological order breaks ties by spec ordinal. Unknown/self/cyclic edges and impossible validation prerequisites have typed refusals. Composite criteria remain whole authored identities. The authoritative queue has exactly one current AC while unresolved entries exist.
2. AC-002. Existing audit mode and slot code bind focused repair planning, implementation and targeted verification to exactly the current AC. A declared validated bounded projection contains its full original requirements/findings, relevant prerequisite facts/reasons, prior evidence, budget/position and tree/checkpoint. Accepted targeted satisfaction alone advances the queue once; other-AC claims and prerequisite side effects cannot close later entries.
3. AC-003. Repair start requires a durable owner-fenced reservation before effects. Discovery/planning are free of repair reservations. One incomplete/retryable blocked repair or one failed targeted verification settles that reservation unsuccessfully once. Success closes once without resetting earlier failures. unsuccessfulBudgetUsed is capped at three, and its third failure blocks with identity/gap/changes/evidence. Whole-set non-shrinking and nested phase semantic-retry counters no longer grant or prematurely exhaust serial attempts.
4. AC-004. Recovery and output admission bind transport loss, interruption, bounded output correction and prelaunch refusal to their precise reservation status. They cannot offer free semantic relaunches, double-count a cycle, reset counters or leave a terminal reserved attempt unaccounted. General process/output protections retain finite limits and unrelated scopes. Cancellation propagates to the existing recovery owner.
5. AC-005. The authoritative recorder's acquired-owner transaction couples serial transitions with phase/ledger/output/checkpoint/workflow changes. Exact replay accepts the same result without mutation; conflicting or stale queue revision/current AC/reservation/owner rejects. Restart/operator resume retains counters/history and evidence. Failed commit cannot publish closure. Post-commit filesystem projection repair reads committed state without replaying reservation/outcome/advance.
6. AC-006. Queue exhaustion requires final-full source audit of every admitted production AC against the current tree, including initially satisfied ACs. Review/resumed downstream permission requires its accepted marker. Only final-full admission reopens demonstrated regressions, with original identity/history and consumed budget intact; exhausted reopen blocks immediately. Source audit cannot run builds/tests and cannot manufacture validation evidence.
7. AC-007. Durable per-AC source disposition and validation-obligation status remain distinct for mixed and test-only criteria. A detached bounded repair snapshot and runtime blocks expose active identity, used/remaining failures, queue position/size, source-closed/unresolved/deferred counts, mode and latest actionable gap/evidence. Unknown legacy values remain absent. No full-completion count derives from total minus gaps.
8. AC-008. Schema-first state/result/focused-projection contracts, shared version/key owners, validator dispatch, parity/rejection tests and typed refusal diagnostics govern every new parse/write seam. Canonical and model-specific acceptance-audit strategies use revision 4 with exact supported historical-policy reconstruction. Stopped pristine legacy adoption preserves original evidence and requires fresh explicit dispositions when old prose is insufficient. Previous aggregate/in-flight/ambiguous repair sources refuse without mutation.
9. AC-009. Authored regression tests at the existing runner, required-start, persistence, isolated SQLite fencing and admission boundaries assert the failure scenarios in test_obligations below, including retained-budget final regressions and no fresh fourth repair after resume. Existing identity/alias/unknown/conflicting-output and immutable settlement regressions remain covered. Each new test names a realistic bug and asserts an observable outcome.
10. AC-010. Existing runtime guidance/strategy prompts define serial scope, failure accounting, final audit and unsafe legacy recovery limitation. Authored skill changes use governed source only when instructions require them. Wiring retains architecture/guard strength, bounded diagnostics, projection limits and cancellation. Audit strategies receive no raw repository/workflow/review authority, and generated install artifacts remain outside committed source.

### 5. Attempt lifecycle and process failures

| Event | Reservation and outcome policy |
| --- | --- |
| Initial discovery or read-only focused planning | No reservation/failure consumption. Existing bounded process/output protections still apply. |
| Refusal before admitted required repair start/reservation | No AC failure consumed. Emit typed refusal under finite existing prelaunch/process limits; no unbounded retries. |
| Accepted reservation, completed repair | Retain the same reservation as awaiting targeted verification, with admitted changes/output/tree evidence. No new attempt for audit. |
| Incomplete repair or retryable blocked repair | Settle that reservation unsuccessfully once, retain partial work/report/evidence, and plan the same current AC again only if budget remains. |
| Targeted audit fails the repaired criterion | Settle the existing reservation once with remaining gap; do not charge a second failure for verification. |
| Targeted audit accepts satisfaction | Settle success, retain prior failures/history, close current and advance once. New current AC gets its own independent failure counter. |
| Output correction | Existing bounded correction policy, currently one output-gate correction, stays bound to the same reservation and output identity lineage. Correction cannot rerun semantic repair for free. Exhaustion after reservation records one unsuccessful outcome and appropriate process block. |
| Transport/acknowledgment loss after durable outcome | Replay retained acceptance/settlement. No new launch, reservation or failure. |
| Transport loss/crash/cancellation after reservation without durable outcome | Retain in-flight reservation. Fenced recovery accepts already durable verification if present; otherwise records exactly one interrupted unsuccessful outcome before any new cycle. Do not swallow cancellation or publish success from uncertain output. |
| Targeted audit/prelaunch failure after repair reservation | It belongs to that existing cycle. If no trusted verification survives recovery, settle one unsuccessful outcome; a prelaunch label cannot make it free. |
| Duplicate or stale callback | Identical admitted outcome replays; changed/wrong-generation output refuses without counter/queue mutation. |

Change PhaseAttemptContinuations.kt and FeatureTaskRuntimeAttemptBudgets.kt only where current serial repair uses broad phase semanticIteration as permission. Do not run another three incomplete/retryable semantic continuations inside each criterion reservation. Each newly attempted repair requires a distinct allowed reservation; same-reservation output correction remains bounded and is not a repair relaunch. Keep existing process-failure/output-gate caps for genuinely process-only work and unrelated phases. Do not enlarge them or claim generally that no repair attempt was consumed when a reserved serial failure was settled. Phase budget resets in beginPhaseAttemptLaunchAfterRequiredStart/restartAttemptBudgetForRelaunch must never alter criterion counters.

### 6. Final-full acceptance and reopening

Empty initial or repaired queues always enter final-audit-required. The final mode examines the full original production catalog against the current admitted tree and retained evidence, including ACs not repaired and initially source-satisfied. Only its accepted result can publish final-audit permission through the authoritative transaction and satisfy the existing review entry gate. Resumed/hydrated paths require the same marker and matching catalog/tree; queue emptiness or targeted satisfied output is insufficient.

A demonstrated regression reopens only named admitted production IDs under the trusted final mode. Retain their history/counters/evidence, admit the regression findings, validate any declared graph changes, and order reopened unresolved entries topologically by the same ordinal rule. Still-satisfied prerequisites remain explicit facts. If a reopened AC has three failures, budget-block immediately without a fourth launch. Otherwise return to focused planning/repair/targeted audit. An operator or ordinary targeted audit cannot reopen/close arbitrary criteria. Later mutation invalidates stale final-audit permission under existing checkpoint/tree admission. Final source audit never executes tests/builds; validation owns deferred evidence.
