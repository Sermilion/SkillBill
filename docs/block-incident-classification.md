# Block incident classification

The rules in `BlockIncidentClassificationRule.kt` evaluate these typed facts in order. The first matching row wins. Every `DIAGNOSED` result still needs available supporting evidence; otherwise the classifier lowers certainty to `SUSPECTED`.

| Failure code or fact | Disposition and evidence | Category | Prerequisite |
| --- | --- | --- | --- |
| `InstallFailureCode.MALFORMED_REPO_LOCAL_CONFIG`, `InstallFailureCode.REPO_LOCAL_CONFIG_FAILURE`, `TelemetryHttpFailureCode.RELAY_URL_UNCONFIGURED`, `RejectedOutputDiagnosticFailureCode.INVALID_CONFIGURATION` | Any disposition | `USER_ENVIRONMENT` | `CONFIGURATION_FIXED` |
| `FeatureTaskRuntimeFailureCode.INVALID_QUALITY_GATE_CONFIGURATION` | Missing or incompatible pack gate declaration or missing required gate command | `USER_ENVIRONMENT` | `CONFIGURATION_FIXED` |
| `non_retryable_policy_conflict`, or `GoalRunnerStopReason.POLICY_BLOCKED` and `DEPENDENCIES_BLOCKED` on `ACCEPTED_GOAL_BLOCK` | Typed disposition or goal stop code | `USER_ENVIRONMENT` | `CONFIGURATION_FIXED` |
| `TelemetryHttpFailureCode.PROXY_REQUEST_FAILED`, `TelemetryHttpFailureCode.PROXY_INVALID_RESPONSE` | Any disposition, including `needs_user_action` | `EXTERNAL_SERVICE` | `EXTERNAL_SERVICE_AVAILABLE` |
| `AcceptanceCriterionRepairStage.BUDGET_BLOCKED`, `FeatureTaskRuntimeFailureCode.PROJECT_QUALITY_GATE_FAILED` | Explicit `failure_subject=project_source` from structured validation evidence, or a current quality-gate finding with that typed subject | `PROJECT_SOURCE` | `PROJECT_EDIT_COMPLETED` |
| `BlockIncidentFailureCode.INVALID_SCHEMA`, `INVALID_VERSION`, `IMMUTABLE_CONFLICT`, `PERSISTENCE`, `QUARANTINE`, `FALLBACK_SPOOL`; `FeatureTaskRuntimePhaseOutputFailureCode.MALFORMED`, `ROOT_NOT_OBJECT`, `DUPLICATE_KEY`, `NO_REPAIR_CANDIDATE`, `AMBIGUOUS_REPAIR`, `REPAIR_LIMIT_EXCEEDED`, `UNSUPPORTED_REPAIR`, `SCHEMA_INVALID`, `PHASE_ID_MISMATCH`, `SEMANTIC_INVALID`, `MULTIPLE_OUTPUT_CANDIDATES`; `FeatureTaskRuntimeFailureCode.INVALID_REPAIR_RECEIPT`, `INVALID_FINDING_VERIFICATION_RECORD`, `INVALID_CHECKPOINT_IDENTITY_SCHEMA`, `INVALID_CHECKPOINT_IDENTITY_VERSION`, `INVALID_QUARANTINE_SCHEMA`, `INVALID_IMPLEMENTATION_ATTEMPT_SCHEMA`, `INVALID_IMPLEMENTATION_PROGRESS_SCHEMA`, `INVALID_PHASE_HANDOFF_SCHEMA`, `INVALID_PERSISTENCE_SCHEMA`, `INVALID_PROJECTION_MEASUREMENT_SCHEMA`, `INVALID_SHARED_EVIDENCE_PROJECTION_SCHEMA`, `INVALID_BUILD_RECEIPT_SCHEMA`, `INVALID_VALIDATION_EVIDENCE_SCHEMA`, `INVALID_READINESS_EVIDENCE_SCHEMA`, `INVALID_ACCEPTANCE_CRITERION_REPAIR_STATE_SCHEMA`, `INVALID_ACCEPTANCE_CRITERION_AUDIT_RESULT_SCHEMA`, `INVALID_ACCEPTANCE_CRITERION_REPAIR_HANDOFF_SCHEMA`, `INVALID_ACCEPTANCE_CRITERION_REPAIR_ADOPTION_SCHEMA`, `INVALID_EXECUTION_IDENTITY_SCHEMA`, `INVALID_WORKER_OWNERSHIP_SCHEMA`, `PHASE_SETTLEMENT_CONFLICT`, `FEATURE_TASK_RUNTIME_CONTRACT_REJECTED`, `MALFORMED_STEP_LAUNCH_ASSIGNMENT`, `INCOHERENT_STEP_LAUNCH_ASSIGNMENTS`, `UNSUPPORTED_EXECUTION_PLAN_VERSION` | `invalid_output` or `process_failure`; typed failure code or available rejected/producer output evidence | `SKILL_BILL_DEFECT` | None |
| Any other `needs_user_action` failure with a nonblank typed code, except `FeatureTaskRuntimeFailureCode.PHASE_ATTEMPT_BUDGET_EXHAUSTED` and `LOOP_EDGE_CAP_EXHAUSTED` | Typed disposition | `USER_ENVIRONMENT` | None, certainty `SUSPECTED` |
| Anything else | No supported typed match | `UNRESOLVED` | None, certainty `UNKNOWN` |

Generic Gradle task headers, malformed or unavailable Detekt/JUnit artifacts, and ordinary JUnit failure/error entries retain `unknown` attribution. Task names, report locations, messages, and exception text do not establish project ownership. A mixed finding set may emit `PROJECT_QUALITY_GATE_FAILED` when at least one current finding has explicit project attribution; unknown siblings remain unknown. Legacy finding maps without `failure_subject` decode as unknown because older observations did not retain causal attribution.

The runtime defect table explicitly lists every supported `BlockIncidentFailureCode`, every `FeatureTaskRuntimePhaseOutputFailureCode`, and the runtime contract failures named in `BlockIncidentClassificationRule.kt`. QA and environment contract failures are excluded. A new failure enum member stays unmapped until an owner adds it deliberately. Failure labels use qualified enum names, such as `FeatureTaskRuntimeFailureCode.INVALID_VALIDATION_EVIDENCE_SCHEMA`; lowercase protocol wire values do not match unless their typed producer converts them at its owning boundary.

No credentials failure literal exists in the current vocabularies. The classifier does not infer credentials or project ownership from reason text, command names, exit codes, or arbitrary log text.
